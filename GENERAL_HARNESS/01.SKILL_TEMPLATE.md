# 01. SKILL TEMPLATE

> 한국어 별칭: 스킬 작성 표준  
> 목적: 모든 `skills/*/SKILL.md` 파일의 공통 구조를 고정한다.  

---

## 0. 스킬 실행 전제

스킬은 하네스의 하위 모듈이다.

| 규칙 | 설명 |
|---|---|
| 상위 규칙 | `00.QUICK_REF.md`, `00.HARNESS_RULES.md`, `04.GATEGUARD.md`, `07.SECURITY_BASELINE.md`, `08.QUALITY_GATE.md`가 모든 스킬보다 우선한다. |
| 충돌 처리 | 스킬 절차가 상위 규칙과 충돌하면 스킬 실행을 중단하고 상위 규칙을 따른다. |
| 위험 작업 | 파일 삭제, 대량 이동, DB/결제/보안 변경은 스킬 단독 판단으로 진행하지 않는다. |
| Report 연결 | 스킬 결과는 필요 시 `06.REPORT_TEMPLATE.md` 또는 관련 Gate로 넘긴다. |
| 인라인 최소화 | 각 스킬의 `## 0. Harness Control Rule`은 2줄 요약만 유지하고, 세부 규칙은 이 문서와 `00.QUICK_REF.md`에 둔다. |

## 1. 스킬 작성 원칙

스킬은 “지식 문서”가 아니라 **특정 작업을 안정적으로 수행하기 위한 실행 절차**다.

좋은 스킬은 다음을 가져야 한다.

| 기준 | 설명 |
|---|---|
| 발동 조건 | 언제 이 스킬을 써야 하는지 명확해야 함 |
| 비발동 조건 | 언제 쓰면 안 되는지 명확해야 함 |
| 입력물 | 어떤 문서/코드/정보가 필요한지 명확해야 함 |
| 절차 | 작업 순서가 초보자도 따라갈 수 있어야 함 |
| 산출물 | 최종 결과물이 무엇인지 명확해야 함 |
| 게이트 | 해당 작업 유형에 맞는 통과/경고/실패 기준이 있어야 함 |
| 인계 | 다음 스킬, Gate, 리포트로 어떻게 연결되는지 있어야 함 |

## 4. Trigger 작성 규칙

Trigger는 “그럴 수도 있음”이 아니라 **사용해야 하는 명확한 조건**으로 적는다.

좋은 예:

```txt
- 새 API 엔드포인트의 URL, Method, Request, Response를 정의해야 할 때
- 기존 API 명세가 프론트/백엔드 구현과 어긋나는지 검수할 때
```

나쁜 예:

```txt
- API 관련 작업일 때
- 백엔드 할 때
```

---

## 5. Do Not Trigger 작성 규칙

Do Not Trigger는 스킬 남용을 막는다.

예시:

```txt
- 단순 오타 수정만 하는 경우
- 이미 승인된 API 명세를 그대로 구현만 하는 경우
- 공식 문서 확인이 필요한 최신 정보인데 확인 없이 추측해야 하는 경우
- 상위 하네스 규칙과 충돌하는 작업인 경우
```

## 6. Gate 작성 규칙

모든 스킬은 최소한 PASS/WARN/FAIL 기준을 가져야 한다.

| 판정 | 의미 |
|---|---|
| PASS | 다음 단계 진행 가능 |
| WARN | 위험도에 따라 진행 가능 또는 사용자 확인 필요 |
| FAIL | 수정 전까지 다음 단계 진행 금지 |

공통 문구만 반복하면 안 된다. 각 스킬의 Gate는 작업 유형별 필수 산출물 기준을 가져야 한다.

예시:

| 스킬 | PASS 기준 예시 |
|---|---|
| `api-design` | URL, Method, Request, Response, Error Response, Auth, Permission이 정의됨 |
| `git-workflow` | 현재 브랜치, 변경사항 보호, 병합 전략, 검증 명령이 확인됨 |
| `security-review` | 인증, 권한, 입력값, 민감정보, 로그 기준이 확인됨 |
| `terminal-ops` | 명령 목적, 작업 디렉토리, 위험도, 실행 결과가 기록됨 |

---

## 7. Handoff 작성 규칙

스킬은 단독으로 끝나지 않고 다른 스킬, Gate, 리포트로 연결될 수 있다.

표기 규칙:

| 대상 | 표기 |
|---|---|
| 스킬 | `skills/api-design/SKILL.md` |
| Gate | `gates/api-gate.md` |
| 문서 | `06.REPORT_TEMPLATE.md` |
| 체크리스트 | `checklists/api-checklist.md` |

예시:

```txt
skills/api-design/SKILL.md → skills/error-handling/SKILL.md → skills/security-review/SKILL.md → gates/api-gate.md → 06.REPORT_TEMPLATE.md
```

## 8. 스킬 생성 전 필수 확인

새 스킬을 만들기 전 반드시 `skills/skill-scout`을 사용한다.

확인 항목:

- 기존 스킬로 해결 가능한가?
- 기존 스킬을 확장하는 것이 나은가?
- 새 스킬이 정말 독립 작업 단위인가?
- `02.SKILL_INDEX.md`에 등록할 수 있는가?
- 상위 하네스 규칙과 충돌하지 않는가?
