## 1-2. 기계적·획일적 결과 방지 검토

> 이 항목은 특정 스타일을 강요하지 않는다. 의도적인 반복·비대칭·강한 표현도 화면 목적과 선택 근거가 있으면 PASS다.

| 항목 | 결과(PASS/FAIL/N/A) | 근거·미해결 항목 |

## 2. FAIL 기준

- 사용자 목표 또는 핵심 행동을 판단할 수 없음
- 필요한 API·데이터가 없는데 확정 디자인으로 처리함
- Loading/Error 상태가 전혀 없음
- 모바일에서 핵심 기능 수행이 불가능함
- 키보드 사용자가 핵심 기능을 수행할 수 없음
- Stack Profile이 활성화되어 있는데 그 금지 규칙을 위반함

## 결과 요약

> 이 표는 **이 Checklist 자체의 판정**이다. 산출물 전체의 최종 판정은 `08.QUALITY_GATE.md §7-2`의 전역 공식(`maxSeverity(Verification, 적용 Gate 전부, 적용 Checklist 전부)`)을 따른다 — 이 표가 PASS여도 같은 산출물의 Gate나 Verification이 WARN/FAIL이면 전체 최종 판정은 그 WARN/FAIL이다.

| 판정 | 기준 |
|---|---|
| PASS | 필수 항목과 §1-2의 검토 항목이 모두 확인되었고, Stack Profile이 활성화된 경우 §1-1도 충족됨 |
| 일반 WARN | 설명이 일부 부족하거나 §1-2의 검토·근거가 불완전하지만 핵심 흐름·상태·접근성 판단에는 지장 없음 |
| 구조 WARN | 문서 연결, 산출물 소유권, 번호 체계, 인계 기준이 일부 모호해 추가 근거 확인 또는 사용자 확인이 필요함 |
| 위험 WARN | 개인정보·권한·결제 관련 화면에서 접근성 또는 보안 관련 정보가 불명확해 사용자 확인 또는 추가 근거가 필요함 |
| FAIL | §2 FAIL 기준 중 하나라도 해당함 |

Checklist 판정 칸에는 `PASS`, `WARN`, `FAIL` 중 하나를 쓰고, WARN인 경우 Report에 `일반 WARN`, `구조 WARN`, `위험 WARN` 중 하나를 함께 적는다.

Checklist 결과는 `06.REPORT_TEMPLATE.md`의 Checklist 결과 섹션에 옮긴다.
