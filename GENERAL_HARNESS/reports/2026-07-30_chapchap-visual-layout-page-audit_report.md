## 1. 작업 요약

- 정의된 WF-001~WF-055 화면은 라우트 별칭을 포함해 모두 연결되어 있다.
- 고객 핵심 흐름은 데스크톱과 390px 모바일에서 큰 가로 넘침이나 고정 요소 충돌 없이 배치된다.
- 신규 구독 신청 화면은 단계 표시, 카드 구획, 하단 고정 CTA가 명확해 현재 디자인 중 완성도가 가장 높다.
- 출시 전 반드시 보완할 시각·구조 문제로 태블릿 관리자 가로 넘침, 320px 전체 화면 넘침, 플랜 첫 화면의 정보 우선순위, 비회원에게 즉시 노출되는 체험 종료 팝업, 푸터 임시 문구를 확인했다.
- 현재 55개 와이어프레임 외에 실제 목적지가 필요한 페이지와 공통 상태 화면이 더 필요하다.
- 이번 작업에서는 디자인과 코드를 수정하지 않고 감사 결과만 문서화했다.

## 4. 잘 구성된 부분

- 웜 화이트 배경, 올리브 포인트, 둥근 카드, 얕은 그림자가 고객 화면 전반에 일관되게 적용되어 있다.
- 각 대표 페이지의 제목과 설명, 카드 본문, 주요 CTA 순서가 대체로 명확하다.
- 구독 신청 화면은 진행 단계와 현재 해야 할 행동이 한눈에 들어온다.
- 모바일 하단 고정 CTA는 하단 내비게이션 위에 위치하며 겹침이 없다.
- 내 구독 요약은 현재 플랜, 다음 배송, 다음 결제를 먼저 보여줘 정보 우선순위가 적절하다.
- 비활성 버튼은 사유 문구를 함께 제공해 색상만으로 상태를 전달하지 않는다.
- 관리자 데스크톱 화면은 KPI, 그래프, 목록의 밀도와 위계가 적절하다.
- 플랜 카드의 hover·focus 강조는 현재 탐색 카드로 이동하고, 포인터가 빠지면 Solo 추천으로 복귀해 의도가 명확하다.

| Major | 고객 푸터가 모든 페이지에서 미완성처럼 보임 | 사업자·약관·SNS 등 “필요한 정보” 문구가 페이지마다 13개 노출 | 확정 정보 연결 전에는 축약된 준비중 푸터를 쓰거나 내부 개발 주석으로 전환 |
| Major | Family 플랜 상세 화면 부재 | Family 카드에는 선택 버튼만 있고 상세 보기 경로와 페이지가 없음 | 기존 플랜 상세 컴포넌트를 데이터 기반으로 확장해 Family 상세 제공 |
| Major | 320px에서 전역 가로 스크롤 발생 | 실제 `clientWidth` 305px, `scrollWidth` 320px, body 최소 폭 320px | 전역 최소 폭 제거 후 320px 콘텐츠 기준으로 여백·그리드 재검수 |
| Major | 모바일 플랜 첫 화면에서 실제 플랜이 보이지 않음 | 소개 다음의 HOW IT WORKS가 첫 화면 대부분을 차지하고 플랜 카드는 아래로 밀림 | 모바일은 플랜 카드를 소개 바로 다음에 배치하고 설명 섹션은 아래로 이동/축약 |
| Minor | 플랜 제목이 어색하게 고아 줄바꿈됨 | 390px에서 강제 `<br>` 뒤 조사 “을”만 한 줄에 남음 | 모바일에서 강제 줄바꿈 해제 또는 반응형 문구·글자 크기 조정 |
| Minor | 일부 터치 영역이 작음 | 홈 헤더 로그인·관리자 아이콘 약 35~37px, 일부 텍스트 CTA 높이 28~32px | 상호작용 영역을 최소 44×44px에 가깝게 확대 |
| Minor | 작은 강조 텍스트의 색상 대비가 약함 | 흰색 대비 muted 4.09:1, primary 2.63:1, secondary 2.45:1 | 12~14px 텍스트에는 더 어두운 토큰을 사용하고 밝은 색은 배경·테두리에 제한 |
| Minor | 키보드·모션 접근성 규칙이 불완전 | 공통 `button:focus-visible`은 있으나 링크·입력 공통 규칙과 `prefers-reduced-motion` 대응 없음 | 모든 인터랙션 요소 포커스 토큰과 모션 감소 미디어 쿼리 추가 |

## 6. 추가로 필요한 페이지

### 출시 전 필수

| 관리자 운영 알림 | 대시보드 알림 아이콘의 목적지가 없음 | 재고, 결제 실패, 배송 예외를 심각도별 표시 |

| 서비스 오류·점검 | 404와 다른 서비스 장애 상황이 필요 | 재시도, 홈 이동, 고객센터 연결 제공 |

## 7. 새 페이지보다 상태로 설계할 항목

- 활성 구독이 없는 사용자의 내 구독 빈 상태
- 목록 로딩, 네트워크 오류, 데이터 없음
- 결제 실패와 재시도
- 배송 조회 정보가 아직 없는 상태
- 메뉴 변경 마감과 일정 미루기 횟수 소진 상태
- 환불 상담 연결 대기·상담 종료
- 체험 종료 팝업의 로그인/비로그인/이미 전환한 사용자 분기

이 항목들은 별도 라우트를 늘리기보다 공통 `ContentState` 계열 컴포넌트와 페이지 내부 상태로 관리하는 편이 정보 구조가 단순하다.
